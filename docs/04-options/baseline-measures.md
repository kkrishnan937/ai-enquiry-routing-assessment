# Proposed baseline measures

None of these operational measures was calculated in this project. The table translates existing investigation questions into proposed definitions, not agreed service standards. No targets are set.

| Measure | Definition | Records needed | Where timestamps would come from | Owner | Status |
|---|---|---|---|---|---|
| First response | Elapsed time from receipt to the first staff response; distinguish an acknowledgement from an answer | Enquiry reference, incoming message and outgoing correspondence, with response type | Received timestamp and timestamp of the first relevant outgoing message | Not recorded in this project | Not available in this project |
| Acceptance | Elapsed time from receipt to receiving-team acceptance, reported separately from first response and resolution | Received record, referral event and attributable acceptance event | Enquiry receipt and service-team acceptance in request history | Not recorded in this project | Not available in this project |
| Resolution | Elapsed time from receipt to the recorded service outcome, without treating acceptance as completion | Enquiry reference, completion event and outcome evidence | Received timestamp and attributable completion timestamp from service records | Not recorded in this project | Not available in this project |
| Transfer/reassignment rate and reasons | Share of reviewed enquiries with a transfer or reassignment, with reasons reviewed separately; a transfer is not automatically an error | Assignment history, old/new team, transfer notes, clarification and any applicable exception | Dated assignment/change-history events and supporting notes | Not recorded in this project | Not available in this project |
| Missing-information rate | Share of reviewed enquiries that required staff to request missing details, with the missing item recorded | Initial enquiry, required-detail guidance, clarification requests and replies | Receipt, request-for-details and reply timestamps in correspondence | Not recorded in this project | Not available in this project |
| Review workload | Active staff effort spent checking guidance, resolving ownership or reviewing suggestions, with waiting time reported separately | Staff activity observations or task records, review outcome, follow-up and relevant request history | Staff-recorded activity start/end and separate request/reply events; operational activity logs were not supplied | Not recorded in this project | Not available in this project |

## Sources and calculation conditions

- [Sponsor memo](../01-plan/sponsor-request-memo.md#questions-to-investigate) asks about first response, acceptance and resolution separately; its [expected response](../01-plan/sponsor-request-memo.md#expected-response) requests baseline measures without targets.
- [Evidence review](../01-plan/evidence-review.md#questions-requiring-further-evidence) identifies assignment reasons and received, response, assignment, acceptance and completion timestamps.
- [Intake account](../03-current-state/intake-process-summary.md#process-described) describes missing-detail requests, referral and acceptance; [elicitation notes](../03-current-state/elicitation-notes-2026-11-08.md#analysis-implications) state that recurrence, delay and repeated effort were not measured.
- [Data readiness](data-readiness-assessment.md) records the absence of an operational extract and effort measurements; [final recommendation](../06-evaluation/final-recommendation.md#follow-on-conditions-for-a-real-organisation) requires review-workload assessment before a real pilot.

Before calculation, agree the review period, included channels, event definitions, handling of duplicate contacts and missing timestamps, and whether elapsed time uses service hours. Those operational rules are **Not recorded in this project**. Keep response, acceptance, resolution, active work and waiting as separate measures. Synthetic examples, model runtime and the acceptance-message dry run cannot supply an operational baseline.
